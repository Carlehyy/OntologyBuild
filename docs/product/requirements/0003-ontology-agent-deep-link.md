## 背景与问题

用户从本体管理进入本体助手时，原流程要求先切换页面，再从已发布本体下拉框中
重复选择刚才查看的本体。该重复步骤增加操作成本，也存在选错相似名称本体的风险。

## 用户与使用场景

拥有本体管理访问权限的用户在浏览本体卡片时，希望直接基于该本体开始查询、
分析或生成行动提案。默认 editor/viewer 同时拥有本体管理和本体助手菜单权限；
自定义角色仍以管理员实际授予的 menu key 为准。

## 目标

- 每张本体卡片提供清晰可发现的“对话”入口；
- 一次点击进入本体助手并自动选择该本体的当前发布版本；
- 浏览器地址表达当前选择，支持刷新、登录回跳与可预测的后退行为；
- 不扩大助手已有的发布状态和授权数据范围。

## 非目标

- 不在助手中查询草稿、试跑或任意历史工作区；
- 不自动创建会话或发送预设问题；
- 不改变本体发布、助手能力边界、HTTP API 或角色菜单配置。

## 用户流程与业务规则

1. 本体卡片在“编辑”“查看”右侧展示“对话”按钮。
2. 当卡片具有 `current_release_id` 时，按钮可用；点击后进入
   `/#/agent?ontology_id=<URL 编码的本体 ID>`。
3. 本体助手加载当前用户可见的本体列表，并仅从具有 `current_release_id` 的条目
   中匹配查询参数；匹配成功后自动选中该本体。
4. 没有当前发布版本时按钮禁用，并说明“本体发布后可进入助手对话”。
5. 用户在助手下拉框中切换或清空选择时，以 replace 方式同步查询参数，避免每次
   切换都增加一条浏览器历史。

## 权限与数据范围

深链仍进入现有 `ProtectedRoute`。没有 `agent` menu key 的用户会得到既有无权限
页面；查询参数本身不授予权限。助手继续以当前用户可读取且包含
`current_release_id` 的列表作为选择范围，并由后端能力接口执行最终授权。

## API、menu key、事件与数据影响

- 新增前端可选查询参数 `ontology_id`，不新增或改变 React 路由路径；
- 不改变 HTTP 请求路径、方法、状态码、响应结构或 OpenAPI operation；
- 不改变 menu key、数据库、Alembic、Celery、SSE、WebSocket、环境变量或
  localStorage key；
- 不产生新的审计事件或持久化数据。

## 异常、降级与审计

- 查询参数为空时维持原有手动选择流程；
- ID 未知、当前用户不可见或没有当前发布版本时不自动选中，也不能绕过发布门；
- 本体列表或助手能力请求失败时沿用页面现有加载和错误反馈；
- 深链只包含本体 ID，不包含令牌、业务数据、模型配置或会话内容。

## 可核验验收条件

1. 1280px 桌面视口下卡片三个操作完整可见，页脚没有横向溢出。
2. 点击可用“对话”按钮后 URL 包含正确本体 ID，助手下拉框和工作台标题均指向
   该本体。
3. 清空或重新选择本体时 URL 与页面状态同步。
4. 无发布版本的按钮有原生禁用语义、可理解标签和原因提示。
5. 直接访问 `/agent`、现有 `/rag` 重定向、登录 `returnTo` 和手动选择行为保持
   兼容。
6. mocked 浏览器契约测试覆盖卡片点击、深链自动选择、URL 同步和响应式无溢出。

## 上线、兼容与迁移约束

该功能为向后兼容的可选查询参数：旧书签 `/agent` 无需迁移，也没有数据迁移。
随常规前端静态资源发布；若出现错误本体选择、页面空白或手动选择回归，回滚本次
前端资源即可，不涉及数据库或后端回滚。真实权限矩阵、登录回跳和生产代理由隔离
staging 验收，不复用其他工作树或生产容器。
