# 编码与重构规范

## 通用

- 一个文件和模块只承担可描述的责任。
- 行数只是审计信号，不是拆分目标；共享同一有序状态机、锁或数据库事务的算法
  可以保持在一个模块，但必须能说明边界，并把独立的契约、查询和副作用适配器
  提取出去。
- 目录移动不夹带格式化或行为修改。
- 不新增无期限兼容代码；兼容入口必须标明退场条件。
- 避免 `import *`，迁移 facade 除外。
- 错误必须保留可定位上下文，但日志不得包含秘密和完整外部响应。

## 后端

- router 负责协议、验证和授权，不承载复杂事务。
- application 层编排 use case；domain 层保存可测试规则。
- 外部服务通过 infrastructure adapter 接入。
- 新 import 使用业务域 canonical path。
- 数据库变更必须通过 Alembic；生产启动不得依赖 `create_all` 修复结构。

## 前端

- 页面通过 feature API/hook 调用后端，禁止新增裸 `apiClient` 调用。
- route、导航和权限元数据最终从 route manifest 派生。
- 通用 UI 不引用具体业务 feature。
- 巨型页面先增加测试，再原样拆分；不得同时改交互和目录。
- 可访问性、键盘操作、加载/空/失败状态属于验收范围。
