# 迭代记录

本目录持续记录每次功能、重构、配置和部署变化的工程证据。

## 命名

```text
YYYY/YYYY-MM-DD-short-topic.md
```

原则上一条可部署 PR 对应一份记录。长期治理项目可以有总览，但每个实际部署
阶段仍需独立记录，不能把多年变更持续追加到一个文件。

## 必填内容

- 状态、负责人、评审人、关联 Issue/PR、commit 和目标分支；
- 背景、目标和非目标；
- 受影响业务域和文件；
- API、数据库、环境变量、权限和兼容影响；
- 变更前基线、实施步骤和可核验验收条件；
- 实际命令、退出结果、跳过项、CI URL 和 artifact；
- 部署步骤、监控指标、观察窗口和回滚触发条件；
- 遗留风险和后续动作。

复制 [template.md](./template.md) 创建新记录。迭代记录不是临时草稿，合并后
必须与实际代码和测试结果一致。状态进入 `Validated` 或 `Released` 后不得
保留“待补充”“待验证”。
